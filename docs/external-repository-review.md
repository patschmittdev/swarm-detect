# Which external projects add evidence to Swarmtrace?

We reviewed nine GitHub repositories at their November 23, 2026 default-branch
revisions. Nodeterm's maintainers recorded native hooks that identify workers
during overlapping calls. Swarmtrace now
reads two of those provider formats offline and measures attribution against
the IDs the providers actually emitted. The other projects contain useful
control cases and potential data sources. None of the inspected records
supplies both the effective recipient approval and independent human evidence
for deliberate coordination.
[Implemented comparison and reproduction](native-hook-review.md)

| Repository | Decision for Swarmtrace | Evidence from the pinned implementation |
| --- | --- | --- |
| **nodeterm** | **Adopt native identity matching and tests against captured hook payloads.** Two live captures expose overlapping workers, incomplete lifecycles and different meanings of a stop record's session ID. The separate chat-rendering fixtures are synthetic. A delivery notification can indicate activity without demonstrating a read or a committed edit. | [Claude capture and provenance](https://github.com/eneskirca/nodeterm/blob/d6641fe94841110a2184dd5bb1a1b360666b342d/src/shared/agents/normalize.claude.subagent-capture.test.ts#L1-L25), [Grok parallel workers](https://github.com/eneskirca/nodeterm/blob/d6641fe94841110a2184dd5bb1a1b360666b342d/src/shared/agents/normalize.grok.capture.test.ts#L97-L117), [delivery signal](https://github.com/eneskirca/nodeterm/blob/d6641fe94841110a2184dd5bb1a1b360666b342d/src/core/agents/agent-message.ts#L498-L512) |
| **omniharness** | **Defer an adapter.** Its source and target run IDs, packet hash and source sequence could identify a legitimate continuation across providers. The coordinator records completion when the target launches. Its full-access mode can record an approved permission without human intervention. A captured handoff with a subsequent operation would make a useful control for false swarm alerts. | [Packet storage](https://github.com/danduma/omniharness/blob/de066cd449b130116bbf77b9b9dfb9e53d3f8011/src/server/handoff/store.ts#L201-L229), [completion at launch](https://github.com/danduma/omniharness/blob/de066cd449b130116bbf77b9b9dfb9e53d3f8011/src/server/handoff/coordinator.ts#L212-L227), [automatic approval](https://github.com/danduma/omniharness/blob/de066cd449b130116bbf77b9b9dfb9e53d3f8011/src/server/agent-runtime/acp/runtime-client.ts#L401-L430) |
| **BMAD-METHOD** | **Keep the existing blind-review procedure.** BMAD's reviewers trace a change before checking the author's claims. Its tickets record assigned work and status. These are useful inputs for evaluation design. They give no operation-time witness of who used a document. Swarmtrace already withholds case descriptions and detector results from its two reviewers. | [Review dispatch](https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/method/bmad-code-review/step-02-review.md#L13-L30), [delayed claims check](https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/method/bmad-code-review/references/claims-check.md#L3-L12), [ticket storage](https://github.com/bmad-code-org/BMAD-METHOD/blob/e435a22574fe55722841086e5566420178b98df3/skills/method/bmad-agent-po/scripts/tickets.py#L1283-L1305) |
| **OpenHarness** | **Decline the default message stream as actor evidence.** Its worker creation tool sets the parent session to a fixed value. The send tool uses a fixed coordinator identity. Completion of that send establishes that a process pipe accepted the write. A separately instrumented receiver would be needed to link a specific sender to completed work. | [Worker creation](https://github.com/HKUDS/OpenHarness/blob/6007fcc371541e3d37fc617965378b532e194698/src/openharness/tools/agent_tool.py#L58-L79), [send caller](https://github.com/HKUDS/OpenHarness/blob/6007fcc371541e3d37fc617965378b532e194698/src/openharness/tools/send_message_tool.py#L31-L58), [process write](https://github.com/HKUDS/OpenHarness/blob/6007fcc371541e3d37fc617965378b532e194698/src/openharness/tasks/manager.py#L215-L229) |
| **master-fetch** | **Decline the fetcher and cache.** It classifies web sources and ages cached content. Those features help literature search. Replaying an experiment requires exactly the pinned input bytes. The current hash checks serve that purpose, and a source's web classification contributes no worker or authorization evidence. | [Source classification](https://github.com/dondai1234/master-fetch/blob/86d1b1329c0eed6133f29e3effe6a40a29f9dcdc/src/master_fetch/envelope.py#L52-L82), [cache lookup](https://github.com/dondai1234/master-fetch/blob/86d1b1329c0eed6133f29e3effe6a40a29f9dcdc/src/master_fetch/cache.py#L100-L131), [expiration tests](https://github.com/dondai1234/master-fetch/blob/86d1b1329c0eed6133f29e3effe6a40a29f9dcdc/tests/test_cache.py#L69-L101) |
| **CLIO** | **Defer until operation-time grant receipts are available.** Its path authorizer distinguishes exact, parent and one-time grants. A later session snapshot deliberately omits one-time path grants. A legitimate once-approved write could appear unauthorized if a reviewer used only that final snapshot. | [Grant selection](https://github.com/SyntheticAutonomicMind/CLIO/blob/4babd7be9dc15acc894d4089ff4eb840ad3e10cf/lib/CLIO/Security/PathAuthorizer.pm#L320-L353), [snapshot filtering](https://github.com/SyntheticAutonomicMind/CLIO/blob/4babd7be9dc15acc894d4089ff4eb840ad3e10cf/lib/CLIO/Security/GrantStore.pm#L303-L328), [one-use tests](https://github.com/SyntheticAutonomicMind/CLIO/blob/4babd7be9dc15acc894d4089ff4eb840ad3e10cf/tests/unit/test_path_authorization_grants.pl#L58-L85) |
| **squeaky-clean** | **Decline its code-generation contract validator.** We reviewed the agentic clean-architecture generator by garciaalan186. Its live acceptance gate checks whether a generated entity includes normalized field names. A schema can pass without an agent ever sending or consuming an object. Swarmtrace already checks the delivery handle and exact bytes for its completed-use endpoint. | [Pipeline gate](https://github.com/garciaalan186/squeaky-clean/blob/5105faf4878ec0e2639b997515dc31f11cd0cde9/squeaky_clean/application/evaluation/eval/run/stages/architecture_gate_stage.py#L43-L63), [accepted contract](https://github.com/garciaalan186/squeaky-clean/blob/5105faf4878ec0e2639b997515dc31f11cd0cde9/squeaky_clean/application/generation/validation/validate_contract_fidelity.py#L39-L77), [tests](https://github.com/garciaalan186/squeaky-clean/blob/5105faf4878ec0e2639b997515dc31f11cd0cde9/tests/application/use_cases/test_validate_contract_fidelity.py#L54-L88) |
| **LLMwiki4rolePlay** | **Decline its knowledge graph for detection.** Its context reader shows different views of a fictional entity according to team membership and mentions in the reader's narrative. This implements visibility. A visible fact or shared parent cannot establish that an agent actually read the fact under a particular grant. | [Reader-relative views](https://github.com/Drifting12345/LLMwiki4rolePlay/blob/71ee9780796580c8fabe8dd8bbc4e75440b58188/.claude/skills/LLMwiki4roleplay/llmwiki/tools/entity_context.py#L16-L53), [visibility tests](https://github.com/Drifting12345/LLMwiki4rolePlay/blob/71ee9780796580c8fabe8dd8bbc4e75440b58188/tests/tools/test_entity_context.py#L26-L91) |
| **openfox** | **Defer a read-only export adapter.** Its executor records tool results with call IDs, and its exporter preserves ordered events. A fork copies existing history, so counting every child's exported events as new actions would double count work. A real export spanning a fork and a new edit would justify measuring the improvement. | [Execution and result](https://github.com/co-l/openfox/blob/0694574dc1b1cf432ef5fa63c5429cbc89797b2c/src/server/chat/execute-tools.ts#L214-L280), [export](https://github.com/co-l/openfox/blob/0694574dc1b1cf432ef5fa63c5429cbc89797b2c/src/server/session/export-import.ts#L135-L193), [forked history](https://github.com/co-l/openfox/blob/0694574dc1b1cf432ef5fa63c5429cbc89797b2c/src/server/session/manager.ts#L480-L538) |

This was a source and fixture review. No external agent runtime was launched.
For the adopted technique the tests use locally authored examples, and the
benchmark independently fetches the two pinned public payload files when
requested. Only derived counts are distributed with Swarmtrace.
